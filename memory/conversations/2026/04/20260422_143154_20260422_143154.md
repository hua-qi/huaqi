## 整体架构

### 后端实现
1. **SSE (Server-Sent Events)**
   - 使用 `Content-Type: text/event-stream`
   - 保持长连接，服务器可以主动推送数据
   - 每条消息格式：`data: {message}\n\n`

2. **WebSocket**
   - 双向实时通信
   - 适合需要双向交互的场景
   - 比 SSE 更灵活但实现更复杂

3. **HTTP Streaming**
   - 使用 Transfer-Encoding: chunked
   - 服务器分块发送数据
   - 浏览器逐步接收并解析

### 前端实现

#### 1. 使用 Fetch API + ReadableStream
```javascript
async function streamChat() {
  const response = await fetch('/api/chat', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ message: userInput }),
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    
    const chunk = decoder.decode(value);
    // 解析并显示 chunk
    updateUI(chunk);
  }
}
```

#### 2. 使用 EventSource (SSE)
```javascript
const eventSource = new EventSource('/api/chat-stream');
eventSource.onmessage = (event) => {
  const data = JSON.parse(event.data);
  updateUI(data.content);
};
```

#### 3. 使用 WebSocket
```javascript
const ws = new WebSocket('wss://api.example.com/chat');
ws.onmessage = (event) => {
  const data = JSON.parse(event.data);
  updateUI(data.content);
};
```

## 实际应用示例

### React 组件实现
```jsx
function ChatStream() {
  const [messages, setMessages] = useState([]);
  const [currentMessage, setCurrentMessage] = useState('');
  
  const handleSend = async (message) => {
    const response = await fetch('/api/chat', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ message }),
    });
    
    const reader = response.body.getReader();
    const decoder = new TextDecoder();
    
    let fullResponse = '';
    
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;
      
      const chunk = decoder.decode(value);
      fullResponse += chunk;
      setCurrentMessage(fullResponse);
    }
    
    setMessages(prev => [...prev, { role: 'assistant', content: fullResponse }]);
    setCurrentMessage('');
  };
  
  return (
    <div>
      {messages.map((msg, i) => (
        <div key={i}>{msg.content}</div>
      ))}
      {currentMessage && <div>{currentMessage}</div>}
    </div>
  );
}
```

## 优缺点对比

### SSE
- ✅ 简单易用，HTTP 协议
- ✅ 自动重连
- ❌ 只能服务器向客户端推送

### WebSocket
- ✅ 双向通信
- ✅ 更低的延迟
- ❌ 实现复杂，需要额外服务器支持

### HTTP Streaming
- ✅ 兼容性好
- ✅ 不需要特殊协议
- ❌ 控制粒度较粗

## 最佳实践建议

1. **选择合适的技术**：根据需求选择 SSE 或 WebSocket
2. **添加心跳机制**：保持连接活跃
3. **实现重连逻辑**：网络异常时自动重连
4. **添加加载状态**：显示正在输入的效果
5. **支持中断**：允许用户停止生成

作为前端开发工程师，你可以根据具体项目需求选择最适合的方案。目前大多数现代 AI 应用倾向于使用 SSE 或 WebSocket，因为它们能提供更好的用户体验。

macbook 使用哪个命令能知道当前所载目录路径

**🤖 Huaqi**

在 MacBook 上，有多个命令可以查看当前所在目录的路径：

## 1. **`pwd`** (最常用)
```bash
pwd
```
- **Print Working Directory** 的缩写
- 显示当前目录的完整绝对路径
- 示例输出：`/Users/子蒙/Desktop/projects`

## 2. **`echo $PWD`**
```bash
echo $PWD
```
- 显示环境变量 `PWD` 的值
- 与 `pwd` 效果相同

## 3. **终端提示符显示**
大多数终端默认会显示当前目录：
- **bash**: `用户名@电脑名:当前目录$`
- **zsh**: `当前目录 %`
- **fish**: `当前目录 >`

## 4. **`dirs`** (查看目录栈)
```bash
dirs
```
- 显示目录栈，第一个就是当前目录

## 5. **使用快捷键**
在终端中：
- **Ctrl + A**: 光标移动到行首（可以看到完整路径）
- **Ctrl + E**: 光标移动到行尾

## 实用技巧

### 1. **显示符号链接的真实路径**
```bash
pwd -P
```
- `-P` 参数显示物理路径（解析符号链接）

### 2. **在 Finder 中打开当前目录**
```bash
open .
```

### 3. **复制当前路径到剪贴板**
```bash
pwd | pbcopy
```

### 4. **快速进入常用目录**
```bash
# 进入桌面
cd ~/Desktop

# 进入文档
cd ~/Documents

# 进入下载
cd ~/Downloads
```

## 示例场景

```bash
# 查看当前在哪里
子蒙@MacBook-Pro ~ % pwd
/Users/子蒙

# 进入项目目录
子蒙@MacBook-Pro ~ % cd Desktop/projects/frontend

# 再次查看
子蒙@MacBook-Pro frontend % pwd
/Users/子蒙/Desktop/projects/frontend

# 复制路径到剪贴板
子蒙@MacBook-Pro frontend % pwd | pbcopy
```

## 前端开发常用场景

1. **查看项目根目录**
```bash
cd ~/projects/my-app
pwd
```

2. **在 VSCode 中打开当前目录**
```bash
code .
```

3. **查看 Node.js 项目路径**
```bash
# 在 package.json 所在目录
pwd
```

**建议**：最常用的就是 `pwd` 命令，简单直接。如果你经常需要复制路径，可以设置一个别名：

```bash
# 添加到 ~/.zshrc 或 ~/.bashrc
alias cpath='pwd | pbcopy && echo "路径已复制到剪贴板"'
```

这样以后只需要输入 `cpath` 就能复制当前路径了！ 🚀
