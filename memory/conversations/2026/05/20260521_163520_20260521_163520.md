前端页面性能指标都有哪些？

**🤖 Huaqi**

子蒙，这个问题很实用，我来帮你梳理一下前端性能的核心指标。不过我注意到你平时更多是通过日记来探索自我认知，突然问起技术话题——是工作里遇到了性能优化的问题吗？

不管怎样，先把干货给你列出来：

---

**核心指标（Web Vitals 体系）**

1. **LCP (Largest Contentful Paint)** — 最大内容绘制
   - 衡量「页面主要内容加载完成」的时间
   - 目标：≤ 2.5s

2. **FID (First Input Delay)** / **INP (Interaction to Next Paint)** — 首次输入延迟 / 交互到下一帧
   - 衡量「页面可交互性」
   - FID 目标：≤ 100ms（已被 INP 取代趋势）

3. **CLS (Cumulative Layout Shift)** — 累积布局偏移
   - 衡量「页面稳定性」，元素突然跳动的程度
   - 目标：≤ 0.1

**其他重要指标**

4. **FCP (First Contentful Paint)** — 首次内容绘制
   - 白屏时间，第一个文字/图片出现的时间
   - 目标：≤ 1.8s

5. **TTFB (Time to First Byte)** — 首字节时间
   - 服务器响应速度
   - 目标：≤ 800ms

6. **TBT (Total Blocking Time)** — 总阻塞时间
   - FCP 到可交互之间的不可响应时长
   - 目标：≤ 200ms

7. **SI (Speed Index)** — 速度指数
   - 页面内容填充速度的视觉感知

8. **TTI (Time to Interactive)** — 可交互时间

**Rails 场景常用工具**
- Lighthouse（Chrome 自带）
- Web Vitals 库（`web-vitals` npm 包）
- Chrome DevTools Performance 面板

## 回合 3

**👤 用户**

CLI 和 macbook 的 iTerm 的区别是什么？

**🤖 Huaqi**

好问题，这两者的关系其实是个「概念 vs 具体实现」的区别：

**CLI（Command Line Interface）** — 概念层面
- 一种**交互范式**（人类通过文本命令与计算机对话）
- 可以是终端模拟器本身，也可以是终端里运行的 shell（bash/zsh），甚至可以是某个命令行工具（git、curl）
- 核心特征是：输入文本 → 输出文本，没有图形界面

**iTerm2** — 具体产品层面
- 一个 **终端模拟器应用**（Terminal Emulator），跑在 macOS 上
- 它是 CLI 的**容器/载体**，负责渲染文本、管理标签页、支持分屏
- 你打开 iTerm，在它窗口里运行的 **bash/zsh** 才是真正的 CLI 环境

---

**打个比方：**

> iTerm2 ≈ 一个「文本剧场」的舞台
> CLI ≈ 舞台上演员说的「台词」和「表演方式」

你坐在台下（看着 iTerm 窗口），演员唱念做打（CLI 命令的输入输出），但舞台本身不是表演，它只是承载表演的地方。

**更直白的类比：**
- CLI 像是「打电话」这种通信方式
- iTerm 像是你的 iPhone 上的「电话 App」

你用 iTerm 这个 App 来做 CLI 这件事，但 CLI 本身并不依赖 iTerm——你也可以用 macOS 自带的 Terminal.app、VSCode 的终端、甚至是 tmux 在 SSH 会话里做同样的事。

---

所以简单总结：**CLI 是「什么」，iTerm 是「用什么」**。😄
