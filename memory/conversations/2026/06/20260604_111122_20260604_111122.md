http 状态 304 是什么意思

**🤖 Huaqi**

子蒙，304 是 **"Not Modified"（未修改）**，属于 HTTP 重定向类状态码（3xx），但实际机制上更像一个缓存优化信号。

简单说事情是这样的：

### 核心机制
浏览器/客户端本地已经缓存了一份资源，带着 `If-Modified-Since` 或 `If-None-Match` 头去问服务器："这东西变了吗？"

服务器检查后发现没变，就不用把完整资源再传一遍，直接回个 **304**——相当于说："没变，用你本地那个就行。"

### 对比一下
- **200**：服务器正常返回资源
- **304**：资源没变，客户端继续用缓存的那份
- **404**：资源不存在

### 实际场景
- 你刷新一个页面时，很多静态资源（CSS、JS、图片）返回 304，表示文件没更新过
- 这比重新下载完整资源快很多，也省带宽
- 304 **不包含消息体（body）**，只有响应头，所以传回来的数据量极小

### 你可以用它来
- 检查浏览器缓存是否生效
- 判断服务端配置的缓存策略（ETag / Last-Modified）是否工作正常
- 排查重复请求问题（如果某些请求频繁 304，可能是缓存策略太保守了）

之前你不是在跟 CI/CD 和团队协作流程打交道嘛，如果你在调试前端资源发布后用户没及时拿到新版本的问题，304 就是你需要留心的地方——有时候资源内容改了但因为缓存策略没更新，客户端可能一直收 304，误以为"没变化"。🔥
